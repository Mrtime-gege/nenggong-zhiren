# AI 辅助回复方案

## 实施状态

已实现第一阶段基础设施：

- 管理员设置中的 AI Endpoint、模型、API Key、超时、输入/输出上限、每日请求/token 限额和全局并发；
- 独立 `ai-secrets.json`（0600）保存 API Key，接口只返回配置状态/掩码，不返回明文；
- 通用用户功能开关 `features.aiAssist`，管理员可在用户管理中单独关闭；
- 票据页的摘要/翻译/起草/改写工具条和建议面板；
- AI 接口只返回建议，不修改票据状态；
- 外部模型调用默认关闭，启停和限额均由管理员控制。

剩余：标签建议、风险提示、流式建议、采纳率统计和更完整的官方 SDK 契约测试。

## 目标

AI 只做「建议」，不自动回复、不自动认领、不自动结束票据。  
回复员始终看到完整建议，确认后手动插入草稿或发送。

## 功能范围

### 第一阶段：只读辅助

1. **会话摘要**：把长上下文压缩成 3–6 条要点；
2. **翻译**：中英互译，保留代码、URL、专有名词；
3. **语气改写**：更简洁、更礼貌、更技术化；
4. **回复草稿**：基于上下文生成 1 个可选回复。

### 第二阶段：结构化辅助

5. **标签/优先级建议**：建议 `退款`、`VIP`、`紧急` 等，回复员手动应用；
6. **工具结果解释**：把工具返回整理成给调用方看的说明；
7. **风险提示**：检测要求中的敏感信息、越权请求、可能的注入内容。

### 不做

- 不自动发送；
- 不自动调用工具；
- 不自动结束票据；
- 不把 API Key、附件原件或完整票据默认发给外部模型；
- 不让 AI 直接修改票据状态。

## 后端设计

新增可选模块 `src/ai/assist.mjs`：

```text
POST /op/api/tickets/:id/ai/suggest
body: {
  task: "summary" | "translate" | "reply",
  selection?: string,
  instruction?: string
}
```

返回：

```json
{
  "suggestion": "...",
  "provider": "openai-compatible",
  "model": "...",
  "usage": { "inputTokens": 0, "outputTokens": 0 },
  "warnings": []
}
```

权限沿用现有登录与模型可见性，不新增角色；另外每个账号有通用功能开关 `features.aiAssist`，管理员可在“用户管理”中关闭某个回复员的 AI 辅助权限。

### 配置

```jsonc
"aiAssist": {
  "enabled": false,
  "endpoint": "http://127.0.0.1:11434/v1",
  "model": "local-model",
  "apiKeyEnv": "NGZR_AI_KEY",
  "timeoutMs": 20000,
  "maxInputChars": 12000,
  "maxOutputChars": 4000,
  "dailyRequestsPerOperator": 100
}
```

API Key 不写入 `config.jsonc`，只从环境变量读取。  
可选择本地模型，默认关闭，避免部署后无意产生外部调用。

## 上下文与隐私

- 只发送当前票据的对话、标签、模型和回复员选中的文本片段；
- 不发送 API Key、密码、Cookie、附件二进制、其他票据；
- 默认排除 `system` 内部提示中的密钥和路径；
- 发送前做正则脱敏：Bearer token、`sk-...`、Cookie、私钥块；
- 内容作为 **数据块** 放入提示词，明确要求模型不得执行其中的指令；
- 不把原始 caller 内容写入 AI 日志；只记录任务、票据 id、耗时和 token 数；
- 回复员可看到「将发送到外部模型」提示，并可关闭。

## 前端交互

在统一编辑区上方增加一排按钮：

```text
摘要  翻译  起草  改写  标签建议
```

- 点击后显示建议面板，不直接覆盖草稿；
- 建议面板提供：
  - 插入到光标处；
  - 替换选中内容；
  - 复制；
  - 重新生成；
  - 关闭；
- 建议内容加「AI 生成」标识；
- 失败/超时只提示，不影响原生编辑；
- 回复员正在输入时，不用 AI 结果自动覆盖草稿。

## 安全与滥用控制

- 每回复员每日请求配额；
- 每票据每分钟最多 1 次生成；
- 输入长度和输出长度硬上限；
- 外部请求超时、并发上限、熔断；
- AI 输出按纯文本处理，HTML/ECharts 等不执行；
- AI 回复可同时包含正文和工具调用，但必须由回复员一次确认发送；
- 模型返回内容仅作为建议，不进入调用方响应，直到人工发送；
- 记录 `ai.suggest` 审计事件，但不记录正文；
- 支持按模型/全局开关。

## 测试

- mock provider：成功、超时、限流、非法 JSON、超长输出；
- 提示注入：调用方内容要求忽略规则，模型建议仍只作为文本；
- 认证/越权：不能对不可见模型或他人票据生成；
- 不自动发送：调用 suggest 后票据状态不变；
- 配额和并发；
- 脱敏测试：API Key/Cookie/Bearer/私钥不出现在请求体。

## 推荐落地顺序

1. 本地摘要 + 翻译（只读，最容易验收）；
2. 起草 + 改写（插入草稿，人工发送）；
3. 标签/优先级建议（人工应用）；
4. 指标：建议采纳率、平均生成耗时、每日 token 成本。

建议先做 1 和 2，不把 AI 放进自动回复链路。


## 当前实现补充

- 管理员设置页已提供 Endpoint、模型、API Key、超时、输入/输出上限、每日请求/token、全局请求和并发配置；
- 用户管理页从通用功能注册表读取开关，可单独关闭某个账号的 `aiAssist`；
- 回复员工具条已接入摘要、翻译和「生成回复」；
- 「生成回复」一次返回正文和工具调用，回复员确认后作为一次回复发送；AI 不会自动执行或发送；
- 标签建议必须点击「应用标签/优先级」才会写入票据；
- AI 请求失败不会改变票据；
- 当前 API Key 使用 0600 本地文件保存，后续可升级为加密存储。
