## 发现与处理

### 0. 票据横向越权：其他操作员可修改/结束/取消票据（严重，已修复）

第二轮针对票据动作做交叉账号测试时发现：

- Alice 认领票据后，Bob 直接调用 `finish`、`chunk`、`release`、`cancel` 均返回 200；
- Bob 可以把内容注入 Alice 的草稿、替她完成回复、放回队列或取消请求；
- `transfer` 有认领人校验，返回 403，但其余动作缺少同样的校验。

根因是动作处理器只校验票据状态和操作员登录身份，没有校验 `ticket.claimedBy === operator`。

修复：

- `chunk`、`finish`、`release` 只允许当前认领人；
- `cancel` 允许队列中的票据、当前认领人或管理员；
- 前端取消按钮同步收紧；
- 新增回归测试：Bob 对 Alice 的票据执行上述动作全部返回 403。

临时实例复测结果：

```text
finish  403 not_ticket_owner
chunk   403 not_ticket_owner
release 403 not_ticket_owner
cancel  403 not_ticket_owner
transfer 403 not_claimant
```

这是本轮测试发现的最高风险问题，已修复。
### 0.1 同一动作的状态矩阵复测

修复后又在隔离实例上按票据状态做了交叉账号矩阵：

| 动作 | queued | claimed | streaming | done |
| --- | --- | --- | --- | --- |
| chunk | 403 | 403 | 403 | 403 |
| finish | 403 | 403 | 403 | 403 |
| release | 403 | 403 | 403 | 403 |
| cancel | 200（未认领，符合设计） | 403 | 403 | 403 |
| transfer | 403 | 403 | 403 | 409 |

管理员：

- `cancel` 任意活动票据：200；
- `transfer` 已认领票据：200，转交后新认领人可以 finish；
- 直接 `chunk` / `finish` / `release` 别人的票据：403。

补充变体：

- 无 CSRF、借用其他会话 CSRF：403；
- `PUT` 动作：405；
- `finish/`、`%66inish`、带 query 的动作：403/404/405，均未成功；
- 回归测试：35 / 35 通过。


### 0.2 设置节类型过宽（低，已修复）

变体测试发现：

- `PATCH /op/api/settings` 传 `{"queue":"x"}` 或 `{"features":[]}` 时返回 200；
- `SettingsStore` 只校验最终值，非法节类型被 spread/忽略，接口语义不严格。

修复：`queue`、`limits`、`features` 必须是对象，否则返回 400。已加入自动化回归测试。

说明：

- `mfa/login-replay` 在 TOTP 30 秒窗口内仍返回 303，这是标准 TOTP 的已知行为，记为设计残余风险；
- `GET` 的 absolute-form 和重复 Host 被 Node 解析为 200；本机没有共享缓存、没有反向代理，未形成实际利用链，但生产反代应拒绝绝对 URI 和重复 Host；
- 图片 URL 的 0 次服务端请求通过本地 listener 验证；`file://`、`javascript:`、gopher 不会被服务端抓取，但票据仍会创建并显示“unsupported image”；
- `X-Forwarded-For` / `Forwarded` / `X-Real-IP` 伪造不影响登录限速，仍会触发 429；
- 前端没有 `innerHTML` / `insertAdjacentHTML` sink，用户内容走 `textContent`；反射型登录错误不回显原始 HTML。

### 1. CSV 导出空用量密钥时 500（已修复）

- 触发：存在从未使用过的 API Key 时请求 `/op/api/usage.csv`。
- 原因：`UsageStore.get()` 对不存在的记录返回 `null`，CSV 行读取 `usage.minute` 抛错。
- 处理：`get()` 改为返回零值用量；新增测试覆盖“无用量密钥 + CSV 公式前缀”。
- 当前结果：200，CSV 中 `=1+1` 会被转义为 `'=1+1`。

### 2. 图片 URL 由坐席浏览器加载（低，隐私）

- 调用方可以传入 `http(s)` 图片 URL，页面会在坐席浏览器里加载。
- 服务端没有代抓，因此不是 SSRF；但恶意调用方可以用唯一 URL 观察坐席 IP/时间。
- 建议：图片代理或域名白名单；如果不需要外链图片，默认只允许 data URL。
- 当前未改，因为会改变图片使用方式。

### 3. 登录接受 `Origin: null`（低）

- 无 Origin 标记的登录仍可能被无头浏览器使用；`Origin: null` 登录返回 303。
- 带 `Origin: http://evil.example` 的登录返回 403。
- 残余风险是登录 CSRF 的边界；建议生产环境要求非空 Origin 或加 `Sec-Fetch-Site` 校验。

### 4. MFA 为可选 TOTP（设计限制）

- 已验证缺失验证码 401、正确验证码 303、关闭 MFA 200。
- 没有恢复码、没有强制管理员 MFA；TOTP 在 30 秒窗口内可重复使用。
- 建议后续增加恢复码、强制策略和最近使用计数器。

### 5. 慢连接/资源耗尽未做容量结论（信息）

- 20 个只发部分头部的本地连接保持 1.5 秒后，健康检查仍为 200。
- 这不是压力测试，不能证明抗 Slowloris；生产建议反代连接/头部超时和连接上限。

### 6. 其他设计事实

- 审计日志是本地追加文件，不是不可篡改账本。
- 所有 operator 都能查看票据；这是当前角色模型，不是越权漏洞。
- 没有全局 API 限速，只有每密钥 RPM/日/月/并发和登录限速。
