# 本地测试流程

> 这是开发目录文档，不随公开运行包发布。

## 目标

每次改动后，用固定流程确认：

1. 服务能从配置文件启动；
2. OpenAI 和 Anthropic 两种请求都能走完「等待—接单—回复」链路；
3. 账号、密钥、配额、审计和持久化状态没有被破坏；
4. 管理页面、输入框、表格和深色主题没有出现明显回归；
5. 真实数据不会被测试污染。

## 隔离原则

测试不能使用正在运行的实例，也不能使用项目根目录的真实数据：

- 测试会把运行文件复制到系统临时目录；
- 临时目录里生成独立的 `config.jsonc`；
- `users.json`、`api-keys.json`、`state.json`、`usage.json` 全部指向临时目录；
- 测试结束后删除临时目录；
- 测试不会发送真实邮件、不会修改真实账号、不会碰生产密钥。

## 自动化测试

在项目根目录执行：

```bash
npm test
```

测试会启动一个临时实例，包含：

- OpenAI Chat Completions；
- Anthropic Messages；
- 管理页面路由；
- 账号登录、CSRF、角色保护；
- API Key 创建、自定义值、模型范围、配额；
- 完成请求跨重启的幂等回放；
- 流式和非流式工具调用；
- 登录限速和安全响应头。

通过标准：

```text
tests 62
pass 62
fail 0
```

失败时先看 `docs/test-output.txt` 和终端中的失败用例名称。不要带着失败继续打包。

## 手工页面检查

自动化测试不能验证视觉，发布前至少检查：

1. 打开 `/login`，确认输入框是深色、焦点边框正常，没有白底；
2. 登录后打开 `/console`，确认工作台没有整体页面滚动；
3. 打开 `/console/users`：
   - 添加用户；
   - 点「编辑」，确认同一表单被填充、用户名锁定、按钮变为「保存修改」；
   - 取消编辑后表单恢复；
4. 打开 `/console/keys`：
   - 创建普通密钥；
   - 创建自定义密钥；
   - 点「编辑」，确认自定义密钥字段隐藏、配额和模型回填；
   - 同名创建，确认转为编辑；
   - 停用/启用、删除；
5. 用一个测试请求走一遍 OpenAI 和 Anthropic 的接单、回复、完成；
6. 重启临时实例，确认完成请求的幂等回放仍可用。

## 持久化检查

用一个临时项目做一次重启检查：

1. 发送带 `Idempotency-Key` 的请求；
2. 接单并完成；
3. 停止实例；
4. 用同一个配置重新启动；
5. 发送同样的请求；
6. 应该得到相同的原始响应，而不是新票据。

等待中的请求在重启后无法恢复原 HTTP 连接，应显示为「服务重启中断」，这是预期行为。

## 隐私检查

提交或打包前执行：

```bash
grep -RIn --exclude-dir=.git --exclude='*.png' \
  -E '/home/|/Users/|192\\.168\\.|sk-[A-Za-z0-9]{12,}|password: ' .
```

应只看到：

- 占位符；
- 示例值；
- 文档中的字段说明；
- 测试文件里专门构造的临时值（测试文件不进入公开包）。

不要提交：

- `users.json`
- `api-keys.json`
- `state.json`
- `usage.json`
- `.env`
- 日志、证书、私钥
- 真实浏览器截图或会话内容
